Agent-Customer 架构梳理

电商 AI 客服桌面应用 ｜ PyQt6 UI + 自研 Agent 框架 + LiteLLM + SQLite ｜ 整理于 2026-11-23

一、总体分层（自上而下）

依赖方向：UI → core/bridge → Channel/Message → Agent → database/utils；模块间用延迟导入避免循环依赖

二、一条消息的完整生命周期

异步链路：asyncio + websockets ｜ 处理器链优先级：关键词命中即短路，未命中走 AI 兜底

三、模块职责一览

模块定位关键文件
ui/PyQt6 界面层，主窗口 + 各功能页main_ui.py、auto_reply_ui.py、Knowledge_ui.py、setting_ui.py
core/DI 容器与全局服务注册（初始化顺序的核心）di_container.py（configure_standard_services）、connection_status.py
bridge/渠道无关的数据结构与发送抽象，隔离 Channel 与 Agentcontext.py（Context/ContextType）、sender.py（ReplySender）
Channel/拼多多渠道接入：WebSocket 连接、重连心跳、消息解析、HTTP APIpinduoduo/pdd_channel.py、core/pdd_message_handler.py、utils/API/
Message/异步消息队列 + worker 池 + 处理器链core/queue.py、core/consumer.py、handlers/ai_handler.py、handlers/keyword_handler.py
Agent/自研 Agent 框架：LLM 客户端、会话管理、工具执行、5 个业务工具custom/customer_agent.py、custom/tool_executor.py、tools/*.py
database/SQLite 持久层 + 双知识库检索 + 商品知识同步models.py、knowledge_service.py、product_sync.py
service/业务薄封装account_service.py、keyword_service.py、knowledge_io.py
utils/通用工具llm_provider.py（供应商路由）、secret_store.py（DPAPI）、logger_loguru.py

四、Agent 内部机制（自研框架要点）

核心循环

  1. 加载会话历史 → 过长则压缩（session_manager）
  2. message_builder 组装 system prompt + 消息列表
  3. llm_client 经 LiteLLM 异步调用 Chat Completions
  4. 若返回 tool_calls → tool_executor 执行后回填结果，继续循环
  5. 产出最终文本 → 交给 ReplySender 发送
工具并发策略：只读工具（查商品/查知识）并行执行，有副作用工具（发卡片/转人工）串行执行。

工具与知识体系

  • @agent_tool 装饰器注册到全局 TOOL_REGISTRY，Pydantic 模型自动生成 schema
  • 5 个工具：商品列表 / 商品卡片 / 商品知识 / 客服知识 / 转人工
  • 双知识库：product_knowledge（商品）+ customer_service_knowledge（售后/物流/退款），jieba 分词检索
  • 商品知识由 product_sync 从 PDD API 拉取后调多模态 LLM 提取入库
身份字段（店铺/账号）来自可信 dependencies 注入，不从用户消息中取，防提示注入越权。

五、数据模型与配置

SQLite 6 张表（temp/channel_shop.db）

  • channels / shops / accounts（密码 DPAPI 加密）
  • keywords —— 转人工关键词
  • product_knowledge —— 产品知识库
  • customer_service_knowledge —— 客服知识库

配置体系（config.py · Pydantic）

  • llm：供应商 / 模型 / API Key（DPAPI 落盘）/ Base URL / 端点信任模式 / 工具策略
  • 六供应商路由：DeepSeek · 火山 · OpenAI-compatible · Kimi · 智谱 · Qwen
  • business_hours 营业时间、prompt.instructions 回复指令
  • 配置变更按账号 profile 快照生效，运行中账号需重启才应用新配置

六、设计亮点与注意点

  • 初始化顺序刚性：config → DI 容器（configure_standard_services）→ db → logger → queue → consumer → status_manager，UI 延迟加载。
  • bridge 层解耦：Agent 与 Message 只认 Context/Reply/ReplySender 抽象，新增渠道（如抖音、淘宝）只需实现 Channel + Sender，不动业务层。
  • 多账号隔离：每个 AutoReplyThread 持有独立 PDDChannel 实例与 profile 快照，共享 ConnectionStatusManager 单例。
  • 健壮性：WebSocket 自动重连 + 心跳；消息队列削峰（默认容量 1000，worker 并发 10）；图片超限时降级为纯文本。
  • 安全：远程端点强制 HTTPS + 证书校验，拒绝元数据/链路本地地址与跨主机重定向；API Key 走 Windows DPAPI。
  • 可扩展点：渠道基类 channel.py、处理器链 handler_chain()、工具注册器均预留了扩展位。
